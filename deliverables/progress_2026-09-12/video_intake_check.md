# Результат: инструмент приёма видео

12 сентября 2026. Статус: **реализован и проверен на искусственном видео**.
Метрик подсчёта пассажиров и подключения к автобусу нет.

## Что теперь можно сделать

Получив разрешённый экспорт регистратора, обработать его одной командой:

```powershell
python development/src/sanas_video/intake.py data/local/cabin_export.mp4 --output development/experiments/artifacts/video-intake/bus01-session01-ch01 --session-id SESSION01 --vehicle-id BUS01 --channel-id CH01 --origin bus
```

Команда выполняется из корня Sanash. Путь к файлу и технические ID заменить
реальными либо документированными псевдонимами. При отсутствии исходника команда
завершится ошибкой без создания результатов. `--times 1 3 5` позволяет взять
кадры из короткого фрагмента вместо значений по умолчанию 10, 30, 50 секунд.

Результаты:

- `metadata.json`: исходный SHA-256, размер, контейнер, кодек, потоки, исходные
  временные метки и версии FFmpeg/FFprobe; фактическое время и хеш каждого кадра.
- `frames/*.png`: кадры первого видеопотока в исходной видимой области;
  стандартная автокоррекция поворота FFmpeg может изменить ориентацию изображения.
- `annotations.csv`: ID сессии, автобуса, канала, времена и пустые поля для
  сцены, наблюдателя, двух разметчиков, согласованного счёта и слепых зон.
- `review.html`: локальная страница просмотра с техническими сведениями.

Существующие результаты не перезаписываются. Повреждённый файл, выход за
длительность и изменение исходника не выдаются за успешный запуск. При ошибке
после начала извлечения остаётся `metadata.json` со статусом `failed`; частичные
кадры из этой папки не считаются принятыми данными.

## Границы результата

Это подготовка данных, не модель загруженности. Времена кадров относятся к
шкале контейнера с приведённым к нулю началом, а не к UTC съёмки.
Мультикамерная синхронизация, удаление повторного счёта, live-подключение,
поддержка фирменного контейнера конкретного регистратора и точность на людях
ещё не проверены. Длинное/тяжёлое видео может потребовать увеличить `--timeout`;
по умолчанию один процесс FFmpeg ограничен 120 секундами.

Следующий внешний шаг остаётся прежним: модель регистратора, ответственный
техник и исходный фрагмент одного салонного канала. Протокол и запрос уже
находятся рядом с этим отчётом. После получения файла мы можем сразу подготовить
кадры и измерить видимость людей по зонам салона.

Основа получения технических метаданных —
[официальная документация FFprobe](https://ffmpeg.org/ffprobe.html).
